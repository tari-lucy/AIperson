# NetTyan — Roadmap

> Фокус: бот идёт к людям, а не ждёт их. Код готов, нужна дистрибуция.

---

## P0 — Голосовая рулетка Nekto.me

Бот заходит в голосовую рулетку и общается с рандомами. Бесконечный поток собеседников, каждый разговор — потенциальный клип.

### Компоненты

#### 1. Браузер и автоматизация сайта

**Задача:** открыть nekto.me, нажимать "Начать", "Следующий", обрабатывать UI-события.

**Варианты:**

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Playwright / Selenium** | Полный контроль, headless, кросс-платформа | Сайт может детектить headless, нужен рендеринг |
| **Playwright persistent context** | Сохраняет куки/сессию между запусками | Чуть сложнее настроить |
| **Ручной Chrome + CDP** | Подключаемся к уже открытому Chrome через DevTools Protocol | Самый надёжный от антибот-детекта, но ручной запуск |

**Рекомендация:** Playwright с persistent context. Если забанят — fallback на CDP к ручному Chrome.

**Что реализовать:**
- `NektoDriver` класс: `start_session()`, `next_partner()`, `disconnect()`, `get_state()` (waiting/connected/disconnected)
- Polling состояния страницы (ждём собеседника / подключены / отключены)
- Новый data_collector: `nekto_collector.py`

**Сложность:** низкая-средняя. Playwright стандартный, сайт простой.
**Баги:** 2-3 (антибот, таймауты, изменения вёрстки)

#### 2. [Optional] Капча и помощь зрителей

**Задача:** при появлении капчи — показать зрителям на стриме и получить ответ через чат.

**Реализация:**
- Детекция капчи: Playwright скриншот → проверка наличия капча-элемента на странице
- Показ зрителям: screenshot → OBS overlay или просто стрим видит браузер
- Ввод через чат: спец-команда `!captcha <ответ>` → NektoDriver вводит
- Fallback: разработчик решает через Gradio UI или Telegram-бот

**Сложность:** низкая. Капча-детекция — CSS-селектор. Ввод — один вызов Playwright.
**Баги:** 1-2 (разные типы капч, таймаут ожидания ответа)

#### 3. Аудио-система (микрофон и звук)

**Задача:** TTS бота → микрофон nekto.me. Голос собеседника → STT.

**Схема:**
```
TTS output → Virtual Cable A (VB-Cable / VoiceMeeter) → Chrome mic input
Chrome audio output → Virtual Cable B → STT input
                                      → OBS capture (для стрима)
```

**Компоненты:**
- **VB-Cable** (2 виртуальных кабеля) или **VoiceMeeter Banana** — маршрутизация аудио
- Настройка Chrome: `--use-fake-ui-for-media-stream` + `--use-file-for-fake-audio-capture` или выбор виртуального устройства в Playwright
- Модификация TTS handler: output device = Virtual Cable A (вместо колонок)
- STT input device = Virtual Cable B

**Что менять в коде:**
- `tts/audio_device.py` — параметр output_device_name, выбор устройства по имени
- `data_collectors/stt/speech_processor.py` — параметр input_device_name
- Конфиг профиля: какое устройство для какого режима

**Сложность:** средняя. Аудио-роутинг на Windows — главный источник багов.
**Баги:** 4-6
- Audio loop (бот слышит сам себя) — нужен echo cancellation или правильный роутинг
- Latency (TTS генерация + виртуальный кабель = 200-500ms дополнительно)
- Chrome не видит виртуальное устройство → нужны флаги запуска
- Уровни громкости (собеседник слишком тихий/громкий для STT)
- Device ID меняется при перезагрузке

#### 4. STT сервис

**Задача:** распознавание речи собеседника с высокой точностью, в идеале — с диаризацией и эмоциями.

**Текущее состояние:** `FasterWhisperSTT` — работает, но:
- Низкая точность на шумном аудио
- Нет диаризации (один спикер)
- Нет эмоций / паралингвистики

**Целевой пайплайн:**
```
Audio stream (Virtual Cable B)
  ↓
VAD (Voice Activity Detection) — silero-vad или webrtcvad
  ↓ (отрезки с голосом)
WhisperX (faster-whisper + alignment + diarization)
  ↓ (текст + timestamps + speaker_id)
[Optional] Emotion classifier (SER — Speech Emotion Recognition)
  ↓ (emotion: angry/happy/sad/neutral)
Event → ctx_chat
```

**Варианты STT:**

| Вариант | Точность | Скорость | Диаризация | Стоимость |
|---------|----------|----------|------------|-----------|
| **Текущий FasterWhisper** | Средняя | Быстрая | Нет | Бесплатно |
| **WhisperX** | Высокая | Средняя | Да (pyannote) | Бесплатно, GPU нужен |
| **Deepgram API** | Высокая | Realtime | Да | $0.0043/мин |
| **AssemblyAI** | Высокая | Realtime | Да | $0.006/мин |

**Рекомендация:** WhisperX локально если есть GPU. Deepgram API если нет — дешёво и realtime.

**Эмоции (опционально):**
- `speechbrain/emotion-recognition-wav2vec2` — бесплатная модель, 4 эмоции
- Или просто анализ тона через LLM (передать текст + "собеседник говорил громко/тихо/быстро")

**Сложность:** средняя-высокая. WhisperX установка + pyannote лицензия. Deepgram API проще.
**Баги:** 3-5
- WhisperX pyannote требует HuggingFace token + согласие на лицензию
- Диаризация путает спикеров при похожих голосах
- Latency: whisperx обрабатывает чанками, не realtime
- VAD false positives на музыке/шуме
- GPU memory (whisper large + pyannote = 4-6GB VRAM)

#### 5. Диалоговый сервис

**Задача:** управление разговором — когда говорить, когда слушать, как прерываться, wake-words.

**Отличие от текущего ChatAgent:** в тексте бот отвечает на сообщение. В голосе — непрерывный диалог с перебиваниями, паузами, реакциями.

**Архитектура:**
```
NektoDialogService
├── State machine: LISTENING → THINKING → SPEAKING → LISTENING
├── Interrupt handler: если собеседник заговорил во время SPEAKING → прервать TTS
├── Silence detector: если молчат > 5 секунд → бот инициирует тему
├── Turn-taking: бот ждёт паузу 0.8-1.5с перед ответом (не перебивает)
└── Wake-word bypass: если слышит своё имя → сразу реагирует
```

**Компоненты:**
- **State machine** — отдельный класс `DialogStateMachine` с состояниями
- **Interrupt** — при VAD активности во время TTS → `ctx_swarm["voice"]["interrupt"] = True` (уже есть механизм)
- **Silence trigger** — таймер, при молчании > N секунд → генерировать реплику (аналог idle_activation который уже есть в ChatAgent)
- **Turn-taking** — задержка между окончанием речи собеседника и началом ответа. Не фиксированная — чем длиннее фраза, тем длиннее пауза (300ms-1.5s)
- **Personality** — отдельный промпт `roulette_charismatic.yml`: разговорный стиль, короткие фразы, вопросы собеседнику

**Сложность:** высокая. Это самый сложный компонент — timing в реальном диалоге.
**Баги:** 5-8
- Бот перебивает (turn-taking слишком агрессивный)
- Бот молчит слишком долго (LLM latency + TTS = 2-5 секунд)
- Бот отвечает на свой же TTS (echo detection)
- Interrupt не успевает (TTS буфер уже отправлен в аудио)
- Двойные ответы (STT распознал чанк, бот начал отвечать, потом пришёл полный текст)
- Wake-word false positives
- Silence trigger срабатывает при фоновом шуме
- Собеседник говорит параллельно с ботом → STT ловит оба голоса

### Сводная таблица компонентов

| # | Компонент | Сложность | Баги | Зависимости | Можно параллелить? |
|---|-----------|-----------|------|-------------|-------------------|
| 1 | Браузер (Playwright) | Низкая-средняя | 2-3 | — | Да |

## P1 — Реакции на видео

Бот смотрит YouTube-видео и комментирует в реальном времени. "Content on nothing" — нужен только видеопоток и VLM.

### Компоненты

| # | Компонент | Описание | Сложность |
|---|-----------|---------|-----------|
| 1 | Frame sampler | Кадры каждые 2-5с или по смене сцены (OpenCV absdiff) | Низкая |
| 2 | Audio STT | Субтитры видео через Whisper или YouTube auto-captions | Низкая |
| 3 | Video-Understanding VLM | GPT-4o / Gemini 2.5 Flash — описание + контекст | Средняя |
| 4 | Reaction timing | Баланс коротких реплик и длинных комментариев | Средняя |
| 5 | Video player control | Пауза/перемотка через pyautogui или browser control | Низкая |

**Сложность общая:** средняя-высокая. Основной challenge — timing реакций и стоимость API (continuous VLM calls).
